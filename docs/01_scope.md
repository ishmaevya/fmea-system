# 01. Область проекта и границы MVP

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Проект | Интеллектуальная система анализа видов и последствий отказов медицинских изделий |
| Объект анализа | Увлажнитель дыхательных смесей |
| Основа | НИРс Ишмаева Я.Д., гр. ИУ5-54бв, МГТУ им. Н.Э. Баумана, 2026 |

Система предназначена для ведения FMEA-анализа медицинского изделия: хранения структуры изделия, ревизий FMEA, оценок риска, связей между отказами, отчётов и подсказок на основе языковой модели.

## 2. Цель и задачи MVP

**Цель:** дать инженеру и менеджеру по качеству единое рабочее место для создания, редактирования, согласования и анализа FMEA-таблицы изделия.

**Задачи MVP:**
1. Хранить изделие, его исполнения, компоненты и вложения.
2. Вести версионные FMEA-ревизии с изменяемым и утверждённым статусом.
3. Рассчитывать RPN и приоритет действий, поддерживать фильтрацию и сортировку.
4. Показывать связи отказов в виде графа.
5. Формировать сводные отчёты и выгружать их в XLSX/PDF.
6. Предлагать отказы, причины и последствия через LLM-заглушку с подтверждением инженером.
7. Разграничивать доступ по трём ролям.
8. Наполнять демонстрационную базу реальными данными изделия.

## 3. Пользователи и роли

| Роль | Назначение | Основные права |
|---|---|---|
| Инженер-конструктор (`engineer`) | Ведёт структуру изделия и черновики FMEA | Просмотр справочников, создание и редактирование изделий, компонентов, черновых ревизий и пунктов FMEA, загрузка вложений, запрос LLM-подсказок |
| Менеджер по качеству (`quality`) | Проверяет и утверждает риски | Всё, что инженер, плюс изменение оценок S/O/D, утверждение ревизий, отклонение подсказок, доступ к отчётам |
| Администратор (`admin`) | Администрирование системы | Управление пользователями и ролями, полный доступ, справочники, аудит |

Правила:
- Инженер не может утверждать ревизию.
- Утверждённую ревизию нельзя редактировать; изменения оформляются новой ревизией.
- Менеджер по качеству может утверждать только ревизии в статусе `review`.
- Администратор не может удалить пользователя, у которого есть утверждённые ревизии; пользователь деактивируется.

## 4. Границы MVP

### 4.1 Входит в MVP

**Страницы:**
1. Вход в систему.
2. Список изделий.
3. Карточка изделия: исполнения, компоненты, ревизии, вложения.
4. FMEA-таблица: редактирование, фильтры, сортировка, массовое сохранение.
5. Граф зависимостей отказов.
6. Отчёты: сводка, топ рисков, сравнение ревизий, экспорт.

**Функции:**
- JWT-аутентификация (access + refresh), выход, профиль.
- CRUD изделий, исполнений, компонентов, ревизий, пунктов FMEA.
- Массовое сохранение строк таблицы.
- Расчёт RPN и приоритета действий.
- Связи между пунктами FMEA и визуализация графа.
- Загрузка и скачивание вложений через MinIO.
- Утверждение и клонирование ревизий.
- LLM-заглушка: предложения по компоненту, применение и отклонение.
- Отчёты и экспорт XLSX/PDF.
- Журнал аудита ключевых действий.
- Демонстрационные данные (`seed_demo`).

### 4.2 Не входит в MVP

- Реальная LLM, RAG и векторная база; в v1 используется заглушка.
- Автоматическое извлечение данных из PDF/DOCX и сканов.
- Электронная подпись и соответствие 21 CFR Part 11.
- Валидация по всему ISO 14971 и автоматическое формирование файла рисков.
- Интеграция с MES/ERP/PLM, LDAP/SSO.
- Совместное редактирование в реальном времени.
- Мобильное приложение и офлайн-режим.
- Мультитенантность и биллинг.
- Управление производственными партиями, серийными номерами и полевыми отказами.
- Полноценная система менеджмента качества предприятия.

## 7. Критерии приёмки MVP

MVP считается готовым, если:
1. `docker compose up --build` поднимает PostgreSQL, Redis, MinIO, backend и frontend без ручных шагов.
2. `make seed` создаёт демонстрационные данные, повторный запуск не дублирует записи.
3. Пользователь входит под каждой из трёх ролей и видит только разрешённые действия.
4. Инженер создаёт изделие, компонент, черновую ревизию и пункт FMEA.
5. RPN пересчитывается при изменении S/O/D и подсвечивается по приоритету.
6. Менеджер по качеству утверждает ревизию; после утверждения редактирование запрещено.
7. Граф отображает связи выбранной ревизии.
8. Отчёт «Топ рисков» строится и выгружается в XLSX.
9. LLM-заглушка возвращает предложения, применение создаёт пункт с источником `llm`.
10. `make test` и `make lint` завершаются успешно.
11. README содержит инструкции запуска, seed, тестов и демонстрации.

## 8. Допущения и ограничения

- Проект выполняется одним студентом в учебных целях; данные — демонстрационные, без реальных пациентов.
- Документы изделия (РЭ, паспорт, ТУ) используются как источник доменных данных.
- PDF АМНК является сканом без текстового слоя и не используется в seed.
- Ограничение курса «не использовать Django» относится к лабораторным работам, а не к дипломному проекту; при необходимости согласуется с руководителем.
- LLM-заглушка не выдаёт себя за реальную модель: в интерфейсе и документации указывается источник предложений.
- PDF-экспорт зависит от наличия шрифта с кириллицей; основной формат выгрузки — XLSX.

## 9. Риски проекта

| Риск | Влияние | Мера |
|---|---|---|
| Сжатые сроки MVP | Часть функций не готова к декабрю | Приоритет: таблица, RPN, отчёты; граф и PDF — во вторую очередь |
| Сложность React Flow | Граф задерживает frontend | Начать с простой раскладки, не делать ручное позиционирование |
| Кириллица в PDF | Некорректный экспорт | DejaVu Sans или отказ от PDF в пользу XLSX |
| Ошибки в НИРс | Замечания на защите | Исправить формулу RPN, группу и copy-paste до сдачи |
| Секреты в репозитории | Утечка данных | Только `.env`, проверка перед коммитами |
| Нехватка реальных данных | Seed выглядит искусственно | Использовать параметры и коды E1–E3 из РЭ/ТУ |

## 10. Глоссарий

| Термин | Определение |
|---|---|
| FMEA | Анализ видов и последствий отказов |
| DFMEA | FMEA конструкции изделия |
| Отказ | Событие, при котором изделие или компонент не выполняет требуемую функцию |
| Причина отказа | Фактор, приводящий к отказу |
| Последствие отказа | Влияние отказа на пациента, оператора или систему |
| S | Severity, тяжесть последствия, 1–10 |
| O | Occurrence, вероятность возникновения, 1–10 |
| D | Detection, вероятность обнаружения, 1–10 |
| RPN | Risk Priority Number, `S × O × D`, 1–1000 |
| Ревизия | Версия FMEA-таблицы изделия |
| Исполнение | Модификация изделия с отличающимися параметрами |
| LLM | Large Language Model, большая языковая модель |
| RAG | Retrieval-Augmented Generation, генерация с опорой на внешние документы |
